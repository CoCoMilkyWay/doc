Optiver - Trading at the Close | Kaggle 比赛第一名方案，作者同时也是目前Kaggle天梯第一人hyd。

![](assets/002.png)

  

比赛目标是预测不同行业的数百只股票的短期波动性，采用optiver提供的API获取秒级别的特征，包括每日540秒的订单簿和成交数据。

![](assets/003.png)

第一名采用的方案如下：

1.  获胜模型：作者的最终模型（交叉验证/私有排行榜得分为5.8117/5.4030）是一个结合了CatBoost、GRU和Transformer的集成模型，权重分别为0.5、0.3和0.2，这些模型共享相同的300个特征。
    
2.  在线学习（OL）和后处理（PP）：在线学习和后处理在最终提交中扮演了重要角色。
    
3.  模型性能：表格展示了不同模型在有无后处理和在线学习的情况下的性能。可以看出OL（online-learning）带来了明显的效果提升
    
    ![](assets/004.png)
    
4.  验证策略：作者使用前400天的数据进行训练，并将最后81天作为验证集，发现交叉验证得分与排行榜得分非常接近。
    
5.  特征（Magic Features）：模型最终使用了300个特征，包括常用的原始价格、中间价格、不平衡特征、滚动特征和历史目标特征。作者使用的一些其他团队尚未分享的有用特征，如基于`seconds_in_bucket_group`的聚合特征和按`seconds_in_bucket`分组的排名特征。seconds\_in\_bucket\_group这个特征处理方法的核心思想是将一天中的交易时间分割成不同的时间段（bucket），然后对每个时间段内的数据进行聚合处理，以捕捉不同时间段的市场行为模式。
    
    ```
    pl.when(pl.col('seconds_in_bucket') < 300).then(0).when(pl.col('seconds_in_bucket') < 480).then(1).otherwise(2).cast(pl.Float32).alias('seconds_in_bucket_group'),
    ```
    
     \*\[(pl.col(col).first() / pl.col(col)).over(\['date\_id', 'seconds\_in\_bucket\_group', 'stock\_id'\]).cast(pl.Float32).alias('{}\_group\_first\_ratio'.format(col)) for col in base\_features\],  
    
    ```
     *[(pl.col(col).rolling_mean(100, min_periods=1) / pl.col(col)).over(['date_id', 'seconds_in_bucket_group', 'stock_id']).cast(pl.Float32).alias('{}_group_expanding_mean{}'.format(col, 100)) for col in base_features]
    ```
    
    ```
     *[(pl.col(col).mean() / pl.col(col)).over(['date_id', 'seconds_in_bucket']).cast(pl.Float32).alias('{}_seconds_in_bucket_group_mean_ratio'.format(col)) for col in base_features], *[(pl.col(col).rank(descending=True,method='ordinal') / pl.col(col).count()).over(['date_id', 'seconds_in_bucket']).cast(pl.Float32).alias('{}_seconds_in_bucket_group_rank'.format(col)) for col in base_features],
    ```
    
6.  特征选择：为了避免内存错误并尽可能多地进行在线训练轮次，作者通过CatBoost模型的特征重要性选择了前300个特征。
    
7.  模型细节：
    

-   CatBoost：通常的训练和预测。
    
-   GRU：输入张量形状为（批量大小，55时间步，密集特征维度），后接4层GRU，输出张量形状为（批量大小，55时间步）。
    
-   Transformer：输入张量形状为（批量大小，200股票，密集特征维度），后接4层Transformer编码器层，输出张量形状为（批量大小，200股票）。作者提到将输出转换为零均值的小技巧很有帮助：
    
    ```
    out = out - out.mean(1, keepdim=True)
    ```
    

9.  在线学习策略：作者每12天重新训练模型，总共5次。作者认为如果采用在线训练策略，大多数团队在使用GBDT时可能只能使用200个特征，因为需要将历史数据与在线数据合并，这会增加内存消耗。
    
10.  数据加载技巧：作者分享了一个数据加载技巧，以每天一个文件的方式保存训练数据，并逐天加载。
     
     ```
     def load_numpy_data(meta_data, features):    res = np.empty((len(meta_data), len(features)), dtype=np.float32)    all_date_id = sorted(meta_data['date_id'].unique())    data_index = 0    for date_id in tqdm(all_date_id):        tmp = h5py.File( '/path/to/{}.h5'.format(date_id), 'r')        tmp = np.array(tmp['data']['features'], dtype=np.float32)        res[data_index:data_index+len(tmp),:] = tmp        data_index += len(tmp)    return res
     ```
     
11.  后处理：作者提到减去加权平均值比平均值更好，因为指标已经给出。
     
     ```
     test_df['stock_weights'] = test_df['stock_id'].map(stock_weights)test_df['target'] = test_df['target'] - (test_df['target'] * test_df['stock_weights']).sum() / test_df['stock_weights'].sum()
     ```
     
12.  不起作用的尝试：作者还分享了一些在他们的情况下不起作用的尝试，包括1dCNN或MLP的集成、GRU模型的多日输入、更大的Transformer模型（例如DeBERTa）以及使用GBDT预测目标均值等。
     

作者在别的discussion中提到的一些信息：

OL带来的提升：0.003 on public lb and 0.01+ on private lb，前十名大部分都采用了OL方案

模型提升：0.015+ on cv

特征数量小于300时验证集得分会急剧下降。
