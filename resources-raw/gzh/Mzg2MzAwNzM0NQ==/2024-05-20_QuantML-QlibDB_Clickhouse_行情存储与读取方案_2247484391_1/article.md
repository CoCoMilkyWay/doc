QuantML-Qlib开发版采用Qlib的底层数据结构，因子采用numpy写入binary file，官方提供了csv导入bin的脚本，参考教程：Data Layer: Data Framework & Usage — QLib 0.9.3.99 documentation

官方代码只展示介绍了全量导入因子的方案。但是实际维护时非常麻烦，不仅要维护交易日历，还要维护成分股信息，以及增量更新因子信息。

为了简化数据维护的流程，我们提供了两套方案，一套采用直接读取数据库，另一套采用sqlserver->csv->bin一键自动更新的方式。

两种方案之前均已介绍过，其中方案一目前支持pg/mysql/mongo，每次查询次数较大，这三种数据库效率均不理想，因此加入了clickhouse数据库支持。ClickHouse是一个高性能的列式数据库管理系统（DBMS），由俄罗斯搜索引擎公司Yandex开发并开源。它被设计用于在线分析处理（OLAP）任务，特别适合用于处理大规模数据集的实时查询和分析

首先安装clickhouse数据库，windows下需要在docker中安装，网上各类教程可以参考。  

安装完成之后为了方便测试，在QuantML-Qlib中加入了写入dump\_clickhouse的脚本，继承自原有的dump\_bin，可以复用以前的csv文件直接导入clickhouse，全市场14年的日频数据导入数据库花费3分钟左右，效率极快。

要实现从qlib直接读取数据库，首先要了解QLIB底层读写数据的逻辑，读取数据的结构为 storage -> provider -> loader -> handler , 大致上是这样的结构。其中又分为calendar,instrument和feature三个子类，分别存储交易日历，成分股信息，以及因子值。数据结构可以参考qlib原有的数据结构。在设计数据库结构时，尽量保持跟原有数据结构一致。

  

所以要改变底层数据接口，重点是修改storage 和 provider，clickhouse\_storage继承原有的storage。在data/data.py建立一个公用的client, 需要根据自己的实际情况修改host和port（clickhouse默认端口8123，框架中使用8133，注意修改），所有的查询均在这个client中实现。我们将client的register在config中，注意这里register的是client的实例，而非class，这样就能确保在storage中调用时，均为这个建立好的client。

```
if getattr(C, "clickhouse_provider", None) is not None:
```

  

storage中调用clickhouse client的代码,其中query\_df是clickhouse\_connect中的方法，能够轻松实现clickhouse到pandas dataframe。

```
def query(self, sql):
```

  

调用时，只需要修改相应的key值即可实现不同数据库读取的切换。具体调用方法参考QuantML-Qlib项目中的examples/workflow\_by\_code.py
