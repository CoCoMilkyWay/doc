在高频金融市场中，价格是由数百万市场参与者（通常具有有限理性和不完美信息）的互动内生决定的。基于智能体的建模 (Agent-based modelling, ABM) 旨在通过模拟微观层面的个体互动来复现宏观市场行为。然而，传统的 ABM 方法依赖于固定的智能体策略，导致其参数空间巨大，难以校准和验证。

多智能体强化学习 (Multi-agent reinforcement learning, MARL) 通过实现更真实的智能体行为并减少自由参数，为这一问题提供了解决方案。但 MARL 的高昂计算成本一直是其在金融领域应用的主要障碍。

**JaxMARL-HFT**  是为解决这一挑战而引入的，它是首个专为高频交易 (HFT)  和市场订单 (market-by-order, MBO)  数据设计的 GPU 加速 MARL 环境。该框架基于 JAX ，扩展了 JaxMARL 框架  和 JAX-LOB 实现 ，专为处理具有不同观察/动作空间和奖励函数的 _异构_ (heterogeneous) 智能体  而设计。

利用 JAX 的强大功能，JaxMARL-HFT 在端到端训练中，实现了与同等硬件上最先进实现相比高达 240 倍的加速。这种显著的速度提升使得研究人员能够处理 HFT 领域中庞大且精细的数据集，并执行稳健 MARL 研究所需的大规模超参数扫描。

该框架通过一个双玩家环境（一个订单执行智能体和一个做市智能体）使用独立近端策略优化 (IPPO) 进行了演示。该实验使用了一整年的 LOB 数据（约 4 亿条订单），结果表明学习到的智能体策略优于标准基准。

### 背景知识

#### 2.1 高频交易 (HFT)

现代金融交易所的核心机制是限价订单簿 (Limit Order Books, LOBs)。市场参与者提交限价单以表达其在特定价格和数量下买卖资产的意图。LOB 作为连续双向拍卖市场，根据价格和时间优先顺序收集和匹配订单。

市场参与者通常按其交易任务分为几类 ：

-   **做市 (Market Making):** 通过同时报出买价 (bid) 和卖价 (ask) 来提供流动性，旨在从买卖价差 (spread) 中获利，同时最小化因积累证券库存 (inventory) 而带来的风险。
    
-   **订单执行 (Order Execution):** 任务是在预定时间段内买入或卖出特定数量的证券 ，其目标是最小化此过程中产生的交易成本（例如市场冲击和滑点）。
    
-   **定向交易 (Directional Trading):** 指参与者旨在通过买卖证券从短期价格波动中获利，而不像做市商那样有提供流动性的明确目标。
    

#### 2.2 多智能体强化学习 (MARL)

MARL 是强化学习的一种形式，其中多个智能体在同一环境中同时学习并采取行动。训练多个智能体的计算需求极高。JAX  等库通过提供 GPU 硬件加速和即时 (JIT) 编译  功能，极大地推动了这一领域的发展。JaxMARL  是一个提供 JAX 加速的 MARL 环境和算法的开源库。

### 相关工作

早期的金融市场 ABM 研究表明，即使是零智能 (zero-intelligence) 代理的简单互动也能复制一些关键的市场现象。然而，后续研究指出，要捕捉更复杂的市场动态，如价格冲击  或订单流相关性 ，需要具备更智能决策能力的智能体。

近年来，(深度) RL 已被广泛应用于定向交易、做市和订单执行等金融交易问题。一些研究已开始利用 MARL 作为更复杂的 ABM 形式。例如，Lussange 等人  使用基于每日股价数据的多 RL 智能体模拟来复现市场统计数据 ，Yao 等人  使用了 LOBSTER  的日内逐笔 (tick-level) 数据。然而，Yao 等人  也特别强调了他们训练设置所需的大量计算资源。

**高计算成本**  普遍限制了 HFT 领域 MARL 的研究规模，或迫使研究人员使用简化的随机背景模型。

虽然在自动驾驶等其他领域已有 GPU 加速 MARL 的成功应用 ，但它们通常依赖于 C++ 引擎 ，而非 JAX。

与其他公开的 HFT ABM 框架（如 MAXE 、ABIDES  和 PyMarketSim ）相比，JaxMARL-HFT 具有两个关键区别。ABIDES-gym  和 PyMarketSim  虽然支持 RL，但它们通常只支持 _单个_ RL 智能体与预定义策略的背景智能体进行交互。PyMarketSim 提供了一种简化的 MARL（策略空间响应预言机, Policy-Space Response Oracles） ，但这并非 MARL 经典的 _同步_ (concurrent) 学习范式。

JaxMARL-HFT 的核心优势在于：

1.  **GPU 加速：** 为 RL 训练提供了显著的速度提升。
    
2.  **经典 MARL 范式：** 采用了完全并发的 MARL 模式 ，允许研究人员使用 JaxMARL 中已有的标准算法实现。
    

### 框架设计

JaxMARL-HFT 是一个在 JAX 中实现的 LOB 级别 MARL 环境 ，它构建于 JAX-LOB  之上，并与 JaxMARL  算法兼容。它遵循经典的 MARL 框架，使多个 RL 智能体能够彼此互动，并与历史 LOB 消息流互动。

![](assets/001.png)

JAX 的运用带来了三个关键性能优势 ：

1.  **`vmap` (矢量化映射):** 允许在数千个 GPU 线程上进行高效并行化。
    
2.  **`JIT` (即时编译):** 自动将操作融合为优化的内核，消除了 Python 的性能开销。
    
3.  **消除数据延迟:** 环境滚动 (rollouts) 和学习更新都在 GPU 上执行，彻底消除了传统实现中 CPU 和 GPU 之间的数据传输延迟。
    

#### 4.1 并行化设计

该框架巧妙地利用 `vmap` 进行了两种不同方式的并行化（如图 1 所示）：

**第一层：跨片段 (Episodes) 并行**首先，数据集被划分为多个单独的“片段” (episodes)。通过 `vmap`，框架可以并行处理这些片段。

与 JAX-LOB 相比，JaxMARL-HFT 在数据加载方面做出了重大改进。它不再是按窗口加载数据 ，而是在初始化时将数据集的所有消息 _以连续形式_ 加载到 GPU 内存中 ，并在运行时通过索引来访问数据。这种设计避免了不必要的内存填充 (padding)，效率极高。例如，一整年 AMZN 订单的预处理数据在 GPU 上仅占用 4GB 内存。

**第二层：跨同类型智能体并行**在每个片段的每一步中，框架会并行处理 _同一类型_ (same type) 的智能体。

之所以不将 _所有_ 智能体简单地用一个 `vmap` 处理，是因为 JAX 的 `vmap` 要求被并行化的函数具有相同的输入和输出数组形状 (shapes)。而 JaxMARL-HFT 的核心目标是支持 _异构_ 智能体 ，这些智能体可能拥有截然不同的观察空间、动作空间和奖励函数。如果强行使用 `vmap`，则需要进行效率极低的填充操作。

因此，框架采用了一种平衡的设计：在外部使用一个 Python `for-loop` 来迭代不同的智能体 _类型_，然后在循环内部使用 `vmap` 来并行处理该 _类型_ 的所有 _实例_ (instances)。这在保持异构灵活性的同时，最大化了 GPU 的并行效益。

#### 4.2 单环境步骤 (Single Environment Step)

一个完整的环境步骤按以下顺序执行：

1.  **行动转换 (Action Conversion):** 将智能体的离散动作转换为 LOB 消息格式。同时，为上一步未成交的订单准备取消消息。
    
2.  **随机 shuffling (Random shuffling):** 随机打乱所有智能体生成的消息，以确保没有智能体在行动顺序上占有优势。
    
3.  **消息增强 (Augment):** 将智能体生成的（取消和行动）消息与历史市场回放的消息流（即背景数据）连接起来。
    
4.  **JAX-LOB 处理 (Processing):** 所有订单消息由 JAX-LOB 模拟器核心按顺序处理。
    
5.  **计算结果 (Calculate step outcomes):** 计算该步骤的奖励、辅助信息、终止标志以及供智能体下一步决策使用的新观察值。
    

#### 4.3 不同的智能体类型

框架中实现了三个 HFT 任务，分为两大类异构智能体 ：

-   **做市 (Market Making):**
    

-   **动作空间：** 提供了三种不同的配置 ，例如：(1) **Spread-Skew** ；(2) **Fixed Quantity** （提供 8 个离散选项，如 "不交易"、"在最佳价格 N Ticks 处挂单"、"跨入价差 1 Tick" 等 \[cite: 182-185\]）；(3) **AvSt**（对 Avellaneda-Stoikov  最优控制解的参数化）。在这些空间中，智能体只选择策略，而订单数量是预先固定的。
    
-   **奖励函数：** 包含基于 Vadori 等人  和 Spooner 等人  的灵活奖励函数，这些函数通常包括价差 PnL 和库存 PnL 两个术语 ，并允许用户调整风险偏好。
    

-   **订单执行 (Order Execution):**
    

-   基于 Frey 等人  的环境。动作空间被离散化，智能体只选择提交订单的价格，而数量是根据任务规模预先定义的。
    

-   **定向交易 (Directional Trading):**
    

-   作为做市类的一个配置来实现 ，但拥有一个独特的动作空间：在最佳价格处发送买单或卖单，或者什么也不做。
    

#### 4.4 IPPO 与异构智能体类型

为了使 JaxMARL  中的标准算法（如 IPPO）适应异构智能体 ，框架进行了扩展。对于 IPPO（独立 PPO），实现方式非常直接：为 _每种智能体类型_ 维护一套独立的网络参数、观察、隐藏状态和动作。在训练和环境滚动期间，同一类型的智能体仍然可以受益于高效的批量操作。所有智能体都保留各自独立的网络权重，它们只能通过环境观察来了解对抗性行为，而不是通过共享权重。

### 实验设置与结果

#### 5.1 速度基准测试

该框架与最接近的 SOTA 开源框架 ABIDES-gym  和 PyMarketSim  进行了比较。需要注意的是，这两个框架主要用于 _单_ RL 智能体训练。为了进行更公平的 GPU 加速量化比较，研究人员还实现了一个 CPU 版本的 JaxMARL-HFT（称为 CPU-MARL）。

![](assets/002.png)

**5.1.1 环境速度**

此测试比较了 _不带学习更新_ 的纯环境吞吐量。JaxMARL-HFT 在 1 个 GPU 上并行运行 4000 个环境，而 ABIDES-gym 和 CPU-MARL 在 64 个 CPU 核上运行 64 个环境。结果显示 JaxMARL-HFT 具有压倒性的速度优势，并且这种优势随着智能体数量的增加而扩大。

![](assets/003.png)

**5.1.2 MARL 训练速度**

此测试比较了完整的 RL 训练循环（包括环境滚动和策略更新）。

-   **JaxMARL-HFT:** 在 1 个 GPU 上并行 4096 个环境，环境滚动和 RL 更新 _全部在 GPU 上_。
    
-   **对比框架:** 在 64 个 CPU 核上并行 64 个环境，环境滚动在 CPU 上，RL 更新在 GPU 上。
    

**结果：** 全 GPU 流程显示出巨大的性能优势。

-   当每类型 1 个智能体时，速度提升约 5-35 倍。
    
-   当每类型 5 个智能体时，速度提升约 95-125 倍。
    
-   当每类型 10 个智能体时，速度提升高达 **200-240 倍**。
    

此外，JAX 的实现使其可以利用 `pmap` 轻松扩展到 8 个 GPU。当每步处理的消息较少时（例如 1 条消息/步），速度优势最大，这有力地证明了消除 CPU-GPU 数据传输瓶颈的好处。

#### 5.2 MARL: 用于 HFT 的 IPPO

实验在一个双玩家环境（一个做市智能体和一个执行智能体同时学习） 中进行，使用了基于 GRU 的循环网络架构。

一个关键挑战是，在高频金融应用中，MARL 的稳定训练极其困难。因此，为了说明 JaxMARL-HFT 的功能，实验被迫使用了 _高度简化_ 的动作和观察空间。

![](assets/004.png)

**5.2.1 训练曲线和学习策略**

-   **做市 (图 3a):**
    

-   使用投资组合价值 (Portfolio Value, PV)  作为代理评估指标。
    
-   结果显示，使用基于库存的 'Spooner' 奖励函数  以及二次库存惩罚项  对训练有益。
    
-   **关键发现：** 尽管损失和奖励在训练和验证数据上均收敛，但 _没有_ 一个学习到的做市策略能实现净利润（平均每笔交易损失约 0.2 Ticks）。然而，作者指出这仍然是一个“出人意料的好结果”。
    
-   **失败归因（假设）：** 一个主要障碍可能是环境设计：在每个 RL 步骤中，智能体上一步未成交的订单会被 _自动取消_。这在价格-时间优先的 LOB 中是一个巨大的劣势。
    

-   **执行 (图 3b):**
    

-   智能体网络很快学会了避免因在片段结束时未完成执行任务而受到的高额惩罚。
    

![](assets/005.png)

**学习到的策略**

-   **做市 (图 4a):**
    

-   智能体学会了 _极少交易_。"DoNothing"（什么也不做）是所有策略中采样频率最高的动作（占比高达 61.7% 至 97.7%）。
    
-   这揭示了奖励函数设计的一个潜在缺陷：如果奖励没有按交易量进行归一化，那么“永不交易”以保证“零损失”就成了一个最优策略。
    

-   **执行 (图 4b):**
    

-   学习到的策略（红线） 通常比 TWAP 基准策略（黑线） _更激进_ ，即更快地完成订单执行。这很可能是为了避免高额的终局惩罚。
    
-   尽管如此，该策略的执行成本（Slippage）平均仍比 TWAP 降低了 0.2 Ticks。这表明智能体学会了在某些时候通过被动交易（而非主动吃单）来捕获价差，从而降低了总成本。
    

![](assets/006.png)

**5.2.2 评估基准策略**

此实验将学习到的 (L) 策略与标准基准 (B) 策略进行了对比（执行基准为 TWAP ，做市基准为 Avellaneda-Stoikov ）。

-   **结果 1 (优于基准):** 学习到的智能体 (L) 在各自的指标上（做市商的 PV 和执行商的 Slippage）均优于基准 (B)。
    
-   **结果 2 (对抗性行为):** 图 5 的矩阵热图显示了一个重要发现。当执行智能体 (EXEC) 面对一个 _基准_ 做市商 (MM Baseline) 时，其滑点为 -21.9 ；而当它面对一个 _学习过的_ 做市商 (MM Learned) 时，其滑点恶化至 -24.2。
    
-   这表明，学习到的做市商对执行智能体更具挑战性。这一发现突显了 MARL 在模拟和理解 _间接市场影响_ 方面的预期优势。
    

### 6\. 结论

本文呈现了首个用于 HFT 的、高度并行化的 GPU 加速 MARL 实验框架 (JaxMARL-HFT)。该框架与 JaxMARL 的 SOTA 算法完全兼容 ，并实现了 HFT 中三个主要任务（订单执行、做市、定向交易）的异构智能体。

与现有SOTA实现相比，JaxMARL-HFT 提供了高达 240 倍的吞吐量提升 ，使研究人员能够利用更大的模型和数据集进行更广泛的超参数扫描。初步结果显示，学习到的策略优于现有基准，并展现出了有前景的对抗性行为。
