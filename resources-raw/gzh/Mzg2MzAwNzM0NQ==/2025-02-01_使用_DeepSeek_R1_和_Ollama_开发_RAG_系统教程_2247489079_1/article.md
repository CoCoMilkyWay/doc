## 为什么选择 DeepSeek R1？

DeepSeek R1 是一个与 OpenAI 的模型相当，但成本却降低 95% 的模型，正在革新 RAG 系统。开发者们喜欢它的原因在于：

-   **专注的检索**：每个答案仅使用 3 个文档片段。
    
-   **严格的提示**：通过“我不知道”的回应避免产生幻觉。
    
-   **本地执行**：消除了云 API 的延迟。
    

## 构建本地 RAG 系统所需的工具

### 1\. Ollama

Ollama 允许你在本地运行像 DeepSeek R1 这样的模型。

-   **下载**：Ollama
    
-   **设置**：通过终端安装并运行以下命令。
    

```
ollama run deepseek-rl # 对于 7B 模型（默认）
```

### 2\. DeepSeek R1 模型变体

DeepSeek R1 的参数范围从 1.5B 到 671B。对于轻量级的 RAG 应用，可以从 1.5B 模型开始。

```
ollama run deepseek-rl:1.5b
```

专业提示：更大的模型（例如 7B）提供更好的推理能力，但需要更多的内存。

```
import streamlit as stfrom langchain_community.document_loaders import PDFPlumberLoaderfrom langchain_experimental.text_splitter import SemanticChunkerfrom langchain_community.embeddings import HuggingFaceEmbeddingsfrom langchain_community.vectorstores import FAISSfrom langchain_community.llms import ollama
```

## 第二步：上传和处理 PDF 文件

利用 Streamlit 的文件上传器选择本地 PDF 文件。使用 PDFPlumberLoader 高效地提取文本，无需手动解析。

### Streamlit 文件上传器

```
uploaded_file = st.file_uploader("上传一个 PDF 文件", type="pdf")if uploaded_file:    with open("temp.pdf", "wb") as f:        f.write(uploaded_file.getvalue())
```

### 加载 PDF 文本

```
loader = PDFPlumberLoader("temp.pdf")docs = loader.load()
```

## 第三步：有策略地分割文档

利用 Streamlit 的文件上传器选择本地 PDF 文件。使用 PDFPlumberLoader 高效地提取文本，无需手动解析。

### 将文本分割成语义块

```
text_splitter = SemanticChunker(HuggingFaceEmbeddings())documents = text_splitter.split_documents(docs)
```

![](assets/003.jpg)

文档分割示意图

## 第四步：创建一个可搜索的知识库

为文档块生成向量嵌入，并将它们存储在 FAISS 索引中。

嵌入允许快速、上下文相关的搜索。

### 生成嵌入

```
embeddings = HuggingFaceEmbeddings()vector_store = FAISS.from_documents(documents, embeddings)
```

### 连接检索器

```
retriever = vector_store.as_retriever(search_kwargs={"k": 3}) # 获取前 3 个块
```

## 第五步：配置 DeepSeek R1

使用 DeepSeek R1 1.5B 模型设置一个 RetrievalQA 链。

这确保了答案基于 PDF 的内容，而不是依赖于模型的训练数据。

```
llm = Ollama(model="deepseek-r1:1.5b") # 我们 1.5B 参数的模型# 创建提示模板prompt = """1. 仅使用下面的上下文。2. 如果不确定，请说“我不知道”。3. 答案保持在 4 句话以内。上下文:{context}问题: {question}答案:"""QA_CHAIN_PROMPT = PromptTemplate.from_template(prompt)
```

## 第六步：组装 RAG 链

将上传、分割和检索整合成一个有凝聚力的管道。这种方法为模型提供了经过验证的上下文，提高了准确性。

### 链 1：生成答案

```
llm_chain = LLMChain(llm=llm, prompt=QA_CHAIN_PROMPT)
```

### 链 2：组合文档块

```
document_prompt = PromptTemplate(    template="上下文:\n内容:{page_content}\n来源:{source}",    input_variables=["page_content", "source"])
```

### 最终 RAG 管道

```
qa = RetrievalQA(    combine_documents_chain=StuffDocumentsChain(        llm_chain=llm_chain,        document_prompt=document_prompt    ),    retriever=retriever)
```

## 第七步：启动网络界面

### 启动网络界面

Streamlit 允许用户输入问题并即时接收答案。

查询会检索匹配的块，将其提供给模型，并实时显示结果。

```
user_input = st.text_input("向你的 PDF 提问:")if user_input:    with st.spinner("思考中..."):        response = qa(user_input)["result"]        st.write(response)
```
