当我们在组内尝试搭建一套 AI 因子自动挖掘 Agent 时，面临的首要问题便是：**我们到底应该使用哪个 LLM？**

是盲目追求性能，给GPT或Claude支付高昂的 Token 账单？还是为了节省预算，直接换上性价比更高的 DeepSeek，或者轻量级的 Gemini-2.5-Flash 和 GPT-4.1-Mini？如果专门选择代码模型如 Qwen2.5-Coder，挖因子的效率会不会更高？

在缺乏量化指标的阶段，这些选型决策大多只能凭直觉。不同的大模型在翻译因子、零样本评估、以及多轮迭代搜索时，真实的边际效应究竟如何？

为了解答这些工程困惑，香港城市大学、上海财经大学、哈罗香港国际学校等机构的研究团队推出了首个专门针对公式化因子挖掘的系统性基准 **AlphaBench**。论文在 CSI300 股票池（2020-2025年真实数据）的回测框架中，深度评测了各大闭源与开源模型。它不仅用数据给出了详尽的“LLM 矿工性价比清单”，更揭示了大模型在零样本因子评估上的致命短板，能够帮不少正在尝试 AI 挖因子的团队少走弯路。

## 问题

在传统的量化研究流程中，公式化 Alpha 因子的挖掘（FAFM）通常依赖于两种方式：

1.  **人工挖掘**：依赖研究员的金融直觉和反复的回测迭代，产出了诸如 Alpha101、Alpha158 等经典因子。这种方法的局限性在于人力成本高，且极易受到研究员自身知识边界的限制，难以快速适应市场风格的切换。
    
2.  **符号回归与遗传算法（GP）**：如 AutoAlpha、AlphaGen 等框架。虽然它们能自动搜索庞大的公式空间，但其搜索过程缺乏经济学逻辑，生成的因子结构极其冗杂，缺乏可解释性，且计算资源消耗巨大。
    

大模型的出现提供了一种新的可能。大模型具备符号推理、代码生成和金融常识，理应能够充当一个“资深研究员”，在保证公式可解释性的同时，实现低成本、高效率的因子合成。

但当我们将大模型引入实际的因子挖掘workflow时，会遇到以下几个致命的真实痛点，这也是 AlphaBench 试图回答和解决的核心量化问题：

-   **语义对齐与低信噪比**：金融市场的核心痛点是极低的信噪比。大模型生成的公式，即使符合语法逻辑（Reliability 高），其表达的经济学含义是否真的与未来的超额收益（RankIC）相关？
    
-   **因子评估的计算成本陷阱**：在迭代搜索因子的过程中，如果对大模型生成的每一个候选因子都进行几年的历史横截面回测，其计算开销和耗时是不可接受的。我们迫切需要大模型本身能扮演“审稿人”（Judge）的角色，通过纯公式的符号结构快速筛选因子。但大模型具备这种 zero-shot 评估能力吗？
    
-   **数据泄漏与前瞻偏差（Lookahead Bias）**：大模型极易在公式中引入  这种未来函数。如何在基准中设计严苛的惩罚机制，确保大模型不会通过“作弊”骗取高分？
    
-   **搜索算法的效率与收敛性**：单次生成（Zero-shot Generation）往往只能得到平庸的因子。要挖出真正强劲的信号，必须依赖多轮迭代。大模型配合不同的搜索算法（如 MCTS、进化算法 EA、链式精炼 CoE），其收敛速度、 token 成本与生成因子的多样性（Diversity）之间该如何平衡？
    

## 核心方法

为了全面剖析 LLM 的因子的挖掘能力，AlphaBench 设计了包含三个核心维度的评测体系。这并非简单的 Prompt 测试，而是一套深度嵌入 Qlib 回测引擎的闭环系统。

### 1\. 因子生成任务

该任务旨在评估模型将人类的研究直觉或宽泛的研究主题转换为可执行 DSL（Domain Specific Language）公式的能力。包含两个子任务：

-   **Text2Alpha**：将具体的自然语言描述直接翻译为公式。例如，输入指令：“计算收盘价的简单移动平均线（默认窗口为10）”，模型需要输出 `Mean($close, 10)`。AlphaBench 精心设计了 84 个简单（Easy）、106 个中等（Medium）和 121 个困难（Hard）的测试案例。困难案例涉及多步逻辑、截面标准化和跨指标复合（例如：计算 z-score 化的10日累积收益，再乘以成交量波动率的倒数）。
    
-   **定向因子挖掘（Directional Mining）**：这是更符合日常研究的场景。研究员不给具体公式，而是给出一个技术分析主题（如：波动率突破、成交量流向、均值回归）。研究团队构建了一个包含 Trend、Volume、Volatility、Pattern、Seasonality、Risk 等 8 个大类、90 个细分技术指标的定向因子分类法（Taxonomy），测试大模型能否在指定主题下自主发挥，生成合规且逻辑自洽的因子。

### 2\. 因子评估任务

既然大模型具有推理能力，那它能否在不进行实际回测的情况下，仅凭公式的“长相”判别因子的优劣？

-   **Factor Ranking**：给定  个候选公式及其简要描述（如 ），让模型挑选出在真实回测中表现最好的前  个。
    
-   **Factor Scoring**：模型需要对单个因子的公式进行深度语义剖析，输出该因子的预测方向（Positive / Negative / Noise），并给出 1 到 5 分的细致评分，指标涵盖四个维度：预测性能（Performance）、稳定性（Stability）、胜率（Win Rate）以及偏度（Skewness）。
    

为了更本质地评估这一能力，AlphaBench 进一步拆解出了两个**原子评估任务**：

-   **信号分类（Signal Classification）**：给出一个因子公式，模型必须准确识别它是能带来稳定收益的“有效信号”（Signal），还是纯粹由于过度拟合产生的“噪声”（Noise）。
    
-   **成对选择（Pairwise Selection）**：同时给模型两个因子公式，模型必须二选一，指出哪一个在实盘回测中的 RankIC 表现更优。

### 3\. 因子搜索任务

在实盘因子库的日常维护中，单点生成因子是不够的。研究员需要让大模型在因子空间内进行自主探索。AlphaBench 实现了三种量化界主流的大模型搜索算法体系：

-   **经验链搜索（Chain-of-Experience, CoE）**：这是一种单线串行的反馈机制。模型从一个种子因子（Seed）出发，每轮生成一个新因子，并获得该因子在 Qlib 上的回测反馈指标（IC, RankIC, IR）。模型结合历史挖掘轨迹（Experience），像人类研究员一样对当前最优因子进行微调、加减算子或优化参数。
    
-   **思维树搜索（Tree-of-Thought, ToT）**：采用分支探索逻辑。每一层由大模型同时生成  个不同的因子（在分支宽度上进行发散），通过 Qlib 进行批量回测评估，利用剪枝规则保留前  个最优秀的节点作为下一层的亲本，向下递归探索。
    
-   **进化算法（Evolutionary Algorithm, EA）**：群体并行的演化策略。将因子池维持在固定大小 。大模型不仅要担任“突变算子”（Gmut），对单个因子的局部节点进行修改，还要担任“交叉算子”（Gcross），将两个不同因子公式的子树进行融合拼接，不断淘汰池子里的弱质因子，促使因子群体向高收益方向收敛。
    

### 4\. 严苛的因子质量控制过滤器

这是 AlphaBench 设计中非常值得实盘团队借鉴的地方。任何模型生成的因子，在进入正式评估前，必须经过严苛的过滤器清洗：

-   **语法与变量校验**：严格检查括号匹配、非法字符。因子公式的算子嵌套深度（Operator Nesting Depth）绝对不能超过 5 层，防止生成不可解释的冗长垃圾公式。
    
-   **算子合法性（Operator Validation）**：只允许使用支持的 Qlib 算子（如表 8 中的 Arithmetic, Special Math, Rolling Statistics, Ranking, Indexing 等），参数数量（Arity）必须完全正确。例如，`Corr(x, y, n)` 必须是 3 个参数，少一个直接废弃。
    
-   **计算效率控制（Efficiency Filter）**：在 CSI300 历史数据上运行，若单因子在两周数据上的计算时间超过 30 秒，直接因计算开销过大而被淘汰。
    
-   **空值校验（Output Validation）**：因子在两周滚动窗口内的 NaN 比例超过 1%，即判定为不稳定因子，直接剔除。
    
-   **Lookahead 强惩罚**：任何使用未来数据的因子（如延迟项  的 Ref 算子），不仅信号方向被强制标记为 Noise，所有数值评分直接打 1 分。
    

## 实验结果

AlphaBench 对包括 GPT-5、Gemini-2.5 系列、GPT-4.1-Mini、DeepSeek-V3、LLaMA-3.1-70B、Qwen-2.5-14B 等在内的十余款主流闭源与开源大模型进行了全面大考。其得出的多项评测结论，对当前的 AI 量化研究极具颠覆性。

### 1\. 生成任务

通过对 Text2Alpha 任务中各模型表现的分析，我们可以得出以下结论：

-   **可靠性（Reliability）极高**：在 Easy 和 Medium 级别下，大多数先进大模型的 Reliability（生成合规、可运行公式的比例）都轻松突破了 90%，甚至 GPT-5 达到了 1.00 的满分。大模型基本解决了公式格式输出的工程痛点。
    
-   **准确性（Accuracy）在 Hard 级别遭遇滑铁卢**：在 Easy 阶段，大模型能够将人类意图完美转化为公式（如 GPT-5 Accuracy 为 0.99）。然而一旦涉及到多步逻辑交互和复杂的截面变换（Hard 阶段），即使是表现最好的 GPT-5，其 Accuracy 也暴跌到了 **0.10**，Gemini-2.5-Flash 也仅为 **0.14**（开启 CoT 后勉强升至 0.20）。
    
-   **代码专有模型的局限性**：实验测试了 Qwen2.5-Coder-7B 和 CodeLlama-70B 等代码大模型。结果表明，虽然它们在写普通 Python 代码上很强，但在 FAFM 任务上，其语义理解能力相比同尺寸通用模型并没有明显优势，在定向因子挖掘的稳定性和准确性上甚至有所落后。
    

![](assets/004.png)

### 2\. 评估任务

这是本篇论文**最值得警醒、也是信息量最大**的结论：**在零样本（Zero-shot）情况下，没有任何一个大模型能够表现出稳定的因子优劣判别能力。**

-   **信号分类与成对选择的惨淡表现**：在 CSI300 股票池上，DeepSeek-V3 对因子进行“有效信号 vs 噪声”分类的准确率仅为 **0.46**，成对选择（哪个更好）的准确率也仅为 **0.48**，这与掷硬币随机猜测无异。强如 GPT-5，其零样本下的成对选择准确率也只在 **0.64** 左右（SP500 上甚至只有 0.52），勉强高于随机基线。
    
-   **为什么 LLM 无法评估因子？** 论文给出了极其深刻的量化分析。大模型做决策完全依赖于纯文本公式。但实际上，因子的真实绩效高度依赖于**执行上下文细节**——如调仓频率（Rebalance Frequency）、信息滞后（Lag Structure）、平滑策略、特定的市场风格等。公式本身的文本结构省略了这些关键物理变量，使得纯公式的性能推断在数学上是一个“欠定问题”（Under-determined Problem）。
    
-   **思维链（CoT）的帮倒忙现象**：在因子评分与排名任务中，引入 CoT（思维链）不仅没有提升模型的判断精度，反而往往引入了极大的方差，导致排名精度（NDCG@K）下降。这是因为冗长的推理链增加了大模型在不确定金融域中的脑补成分，使其判断逻辑变得更加僵化、偏离实际。
    

### 3\. 微调（SFT）的魔法

既然零样本评估走不通，利用有监督微调（SFT）进行纠偏的效果如何？论文在 GPT-4.1-Mini 上使用少量带标注的因子的历史绩效数据进行了微调实验，结果呈现出极具对比性的趋势：

-   **噪声分类任务上的微调：彻底失效**。SFT 后的模型在 Noise Classification 上的 F1 分数和召回率反而大幅下降。这表明二分类任务会让模型极易陷入过度拟合，强行去记忆特定市场环境下的噪声模式，丧失了泛化能力。
    
-   **成对选择任务上的微调：表现惊艳，实现跨市场泛化**。在成对选择（Pairwise Selection）任务上，经过微调后，GPT-4.1-Mini 在 CSI300 上的测试准确率从原本的 **0.44** 暴涨到了 **0.83**（CoT 下达到 **0.86**）。更为关键的是，这种基于相对比较的学习展现出了极强的**跨市场迁移能力**：在 CSI300 上微调的模型，直接去评估从未见过的美国 SP500 市场因子，成对选择准确率依然能保持在 **0.64**（CoT 下达 **0.64**）。
    
-   **为什么成对选择 SFT 如此有效？** 因为相对排序任务迫使模型学习的是公式之间更本质的**通用结构特征**——例如：算子单调性、窗口大小的交互逻辑、分母防零溢出的鲁棒性、以及量价组合的合理性。这些结构特征在不同股票市场之间是高度通用的，不易受到单一市场收益分布漂移的影响。
    

### 4\. 搜索任务

在迭代搜索的测试中：

-   **算法对比**：在 CoE、ToT 和 EA 三种搜索范式中，**进化算法（EA）展示出了最好的整体性能**。EA 能够最大程度地压榨大模型的符号变异与杂交能力，使因子池整体的有效性（IC）和多样性（Diversity）迅速向右上角收敛。
    
-   **性价比之王**：Gemini-2.5-Pro 在原始搜索质量上表现极其亮眼，但其 Token 成本和延迟居高不下。GPT-5 展现了极佳的均衡性。而对于追求性价比的实盘团队，**Gemini-2.5-Flash** 或 **GPT-4.1-Mini** 是极为理想的 Agent 执行器，它们能以微小的性能折损，换取极高的搜索速度和极低的 Token 账单。
    
-   **大模型突变温度（Temperature）控制**：实验表明，挖掘因子时 Temperature 并非越高越好。过高的 Temperature（如 1.5）虽然能带来因子的多样性，但会导致生成大量不合规公式，急剧拉升 Search Cost（单次成功生成所需的重试轮数）；而温和的 Temperature（如 0.75）在搜索效率、因子收敛速度和多样性之间能取得最佳折中。
    

### 5\. 因子挖掘中的“死穴”

-   **词沙拉现象（Word Salad Phenomenon）**：在搜索或者生成任务中，如果开启了较长的 CoT 且将 Temperature 设得较高，一些模型（包括强大的 GPT-4.1-Mini 和 LLaMA3.1-70B-Instruct）会在输出 JSON 的 CoT 字段中产生完全语无伦次、随机无意义的乱码字符和符号拼接（如图 16 所示）。量化团队在部署 Agent 时，必须在 Parser 端建立异常拦截机制，检测此类“幻觉爆发”。
    
-   **成本控制与 Prompt Caching**：团队在做复现时，Token 消耗是不可忽视的。AlphaBench 的测试表明，即便使用像 DeepSeek-V3 这样极具性价比的商业大模型，在不加控制的情况下跑完所有 benchmark 任务也会消耗庞大的 Token。幸运的是，大模型挖掘公式的 System Prompt 极其冗长（因为包含了极其详细的算子规范说明，如图 7 所示），**DeepSeek-V3 的 Prompt Caching（提示词缓存）机制在这里能实现高达 85% 的缓存命中率**，直接砍掉了大部分的重复输入开销。
    

## 一些建议

如果你打算参考这篇论文，在你们团队内部搭建一套基于大模型的 Formulaic Factor Mining Agent，以下是我个人的一些建议

### 1\. 放弃幻想，绝对不要依赖大模型去 Zero-shot 过滤因子

如果你指望写一段精妙的 System Prompt，丢给 GPT-4 几个公式，问它“哪一个能在下周的截面选股里跑出高 RankIC”，可以明确地告诉你：放弃这个想法。大模型零样本下的判断准确率就是 50% 左右。

-   **复现改进点**：在你的 Agent 流程中，**因子初筛（Filter）必须依赖两阶段模式**。大模型仅用来进行“语法与 Lookahead 校验”（硬性规则，完全可以用 Python AST 解析器替代，成本更低），或者将其微调成一个成对比较器。不要让它直接做绝对数值预测。真正的性能评估必须老老实实地回传给 Qlib 或自研的 C++ 截面回测引擎，用历史数据说话。
    

### 2\. 必须引入 AST 结构表达与执行元数据

论文指出，大模型无法零样本理解因子的根本原因，在于公式缺乏执行上下文。

-   **实盘微调建议**：如果你要对大模型进行 SFT，不要直接输入 `Div(Sub($close, $open), $open)` 这样的纯文本字符串。你应该：
    

1.  将公式解析为 **抽象语法树（AST）** 或算子图的结构化 JSON 丢给大模型；
    
2.  在输入中明确**补齐执行元数据**（如：调仓频率=5日横截面，计算滞后=1天，板块=中证800，处理 NaN 方式=均值填充）。只有把这些物理变量作为超参数喂给大模型，它才有可能真正理解公式的物理意义。
    

### 3\. 构建高 contrasted 的 pairwise 训练集

论文中 SFT 成功的关键在于：**成对样本的构建方式**。

-   **复现细节防坑**：不要盲目去随机两两配对因子。你应该参考论文的设计：从你的历史回测因子库中，抽取一部分确定是 Noise 的因子（如 ），和确定是 Signal 的因子（如  且 ）。将“一好一坏”强行配对作为正负样本喂给模型进行有监督训练。这种拉大特征差异的极简设计，能够防止模型在模糊边界上产生过拟合，也是保证微调模型能跨市场泛化的核心技术决窍。
    

### 4\. 严防大模型在 EA 杂交中的“算子爆炸”

大模型在担任进化算法（EA）中的 crossover 杂交算子时，非常喜欢制造逻辑极其复杂、层层嵌套的“垃圾公式”（例如把好几个高维的 Power 和 Exp 嵌套在一起）。

-   **复现硬性限制**：在你的 Agent 控制代码中，必须写死硬性过滤逻辑：
    
    ```
    if formula.get_nesting_depth() > 5 or "Ref" in formula.get_lookahead_terms():    reject_and_retry()
    ```
    
    不要试图用 Prompt 去口头警告大模型“请保持公式简洁”，因为在多轮演化后，大模型必然会失控。唯有配合代码层面的 AST 树深检测和未来函数检测，才是唯一的物理安全网。
    

## 结论

大模型在金融领域的应用，关键点并非在于大模型自身参数规模的盲目扩张，实际上应该聚焦于**大模型与量化回测引擎的深度协同以及特定评估任务的微调对齐**。将大模型定位为一个“富有创造力的变异/杂交算子生成器”，同时将严格的回测作为其最终约束，才是当前大模型在量化选股因子挖掘中唯一可行且具备实盘潜力的正确打开方式。
