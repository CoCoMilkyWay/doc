虽然AI问世已经两年有余，但我了解到大多数人用AI还停留在提问阶段：prompt是一次性的，上下文没法复用，也没有标准化流程。AI的工作效率被大大低估了。

发现大家对AI的压榨程度还很低，我有了写这篇文章的念头。本篇文章中，我会分享我是怎样使用AI的，包括怎么封装Skill，如何构建自己的工作流。

每个人都不应该把自己落地到最底层的工作中，在当下，你自己就是老板，你从AI中雇佣数据分析师、因子研究员、风控、研报助理等岗位。

一.把你可复用的技能打包成Skills

量化交易中有非常多重复性的专业流程，非常适合打包成skill。比如：

数据获取

数据标准化

因子检查

回测质检

行业中性化

风格暴露检查

容量分析

风险归因

策略复盘

我把工作中有很高重复度，会来回做的事情拿出来，把它们打包成一个“技能包”，以后每次做到同样的事情时，给AI一个指令让它直接调用。

这件事就相当于我找了一个打工人，skills就是分配给打工人的工作内容，每当我需要打工人为我干活时，我只需要用一句话通知他应做的事情。

有三种类型的skills：

-   代码型skills：适合确定性强的代码任务，比如生成图表、计算收益率、导出PDF、批量重命名文件等。这类任务直接写成脚本调用。
    
-   流程型skills：固定一套做事情的流程。比如每天浏览外盘信息：
    

**1.** 查看美股三大指数

**2.** 查看纳斯达克、标普、道琼斯表现

**3.** 查看美元指数、美债收益率、黄金、原油

**4.** 查看科技股、AI 股、中概股表现

**5.** 提炼影响 A 股或港股的核心变量

-   判断型skills：你拟定一套判断框架，让AI按照你的判断框架来分析。比如判断是否买入一只科技股票，可以这样列出几条判断逻辑：
    

**A.事件重要性**：是否有新品发布、销量数据、产业政策？

**B.逻辑强度**：是否会带动上游零部件、消费电子、AI 终端？ 

**C.资金认可**：板块有没有放量，龙头有没有走强？

**D.位置判断**：是刚启动还是已经高潮？

**E.风险收益**：现在追进去值不值？

这样只需要通过一句简单的指令“帮我看看外盘发生了什么？”、“这只股票值不值得现在买入？”就能调用skills的技能包了。

像“撰写一篇文章”这样的工程项目，所需要的skills可以分成几个大类，每一个skill边界清晰，并且输入和输出被严格约束。

我还做了一个“策略生成器skill”，包括数据获取与标准化，策略池生成，撰写策略代码与回测。拿“数据获取与标准化”这一步来说， 封装成skill就相当于把确认数据源、检查字段、处理缺失和异常值等工序打包成了一套固定的工作流程，就相当于你雇佣了一个数据岗位的熟手，每当需要获得标准化的数据时，你只需要用一句话“调用数据获取与标准化skill，给我处理过后的2004-2025年上证A股全部价格数据”。

一句简单的指令，就把获取数据、时间区间、字段检查、降频处理、缺失和异常等等环节一网打尽。

tips：怎么创建自己的skills？

1.先和AI讨论，让AI给出一个具体的skill.md文档

2.对skill.md修改后加载到skill库

二.让workflow成为你的另一个复制

skill是某一项具体的能力，workflow就是把这些能力串起来的工作流程。

在量化投研流程中，workflow是一条完整的投研流水线，它决定一个项目应该以什么顺序推进：

 → 获取数据

→ 数据标准化

→ 构建因子

→ 回测验证

→ 风险归因

→ 策略优化

→ 实盘跟踪

→ 复盘总结

skill是这条流水线上的一个标准动作：

 数据获取与标准化 Skill  

  

 →检查数据源

→ 统一字段

→ 处理复权

→ 检查缺失值

→ 排查未来函数

→ 输出标准化数据表

回测检查 Skill  

   

 → 检查交易成本

→ 检查滑点

→ 检查过拟合

→ 检查幸存者偏差

所以，workflow的价值不只是“提高效率”，而是让投研方法可以被复制。

workflow可以把过往的投研经验沉淀下来，比如复盘发现某些策略经常会死在交易成本上，就可以把“交易敏感性检查”作为一个标准加入workflow。
