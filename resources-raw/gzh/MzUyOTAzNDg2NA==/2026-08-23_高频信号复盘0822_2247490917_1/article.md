# 经过数日数夜的修修补补，程序层面的BUG基本趋于稳定。接下来的重点进入因子及模型持续迭代研究中。

#   

# 简单的说下本套系统：

# 1.系统底层：基于C++底层架构，主要借鉴了功夫量化的底层实现（目前量化开源系统中，普惠到众多量化爱好者的开源系统，功夫量化、wondertrader两个C++底层交易架构，vnpy基于python的量化研究架构，是我持续跟踪和学习的3个系统，不断增加自己的理解，再次感谢作者的开源精神。）。

# 2.系统架构：多年前基于CTP的架构资料复现了CTP的后台（含前置、排队、仲裁、交易、风控、结算构成的多进程、组播通讯的交易架构），但本次系统基于单账户单策略交易背景，采用了单进程多线程架构，在code层面并发，在code内部进行串行处理，虽然在处理截面和时序模型上有些许不同，但基本逻辑基本按这个。当然这是一个纯软件架构，和目前一些基于FPGA的架构没法相提并论。

# 3.核心技术：异步日志、共享内存、绑核、以及c++一些编程素养（主要来自对optiver一些分析，我在高频交易系统系列文章中有写，借助AI逐渐纳入到了自己系统优化中），核心技术这这么几点，能把扣到每个细节，每个逻辑每行代码就足够了。

# 4.外围局限性：基于目前行业交易接入门槛的合规要求，以及未来交易技术平权的大趋势，单纯依靠速度获取收益的门会越来越窄，甚至关闭。需要调整系统的收益来源方向，强化预测能力，弱化时延的影响。具体技术对接需要和自己账户对应的QS谈。

# 5.核心策略: 基于实时订单流构建高频时序因子，通过线性模型预测不同周期收益，形成多周期叠加的交易信号。同时支持了单标的日内回转交易以及基于低价股的订单薄挂单做市。

# 6.系统运维：单进程启动，盘中监控，盘后自动复盘全部脚本化。
