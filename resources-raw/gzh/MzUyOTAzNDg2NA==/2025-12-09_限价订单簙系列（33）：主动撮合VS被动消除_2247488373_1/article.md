# 合成订单簙有两个逻辑：“撮合法”和“成交消减法”。

#   

# 合成订单簙一般有两个场景：根据实盘实时逐笔行情合成订单簙 和 基于历史的逐笔行情静态数据重建历史订单簙（注：若自身可以把实盘实时合成的订单簙能归档储存下来，则不需要进行这一步。）。

#   

# 针对不同场景，我们采用不同的订单簙合成逻辑，也可以混用交叉验证。

#   

# 订单簙的用途很多，目前主流的主要是做市策略、高频日内策略、基于订单簙的高精准回测。

#

1.撮合法（Matching Method） 

撮合法是一种主动式订单处理机制。

其核心特点是收到新订单后按照交易所“价格优先，时间优先”进行订单簙处理流程，无需等待后续信息。

该方法核心逻辑是判断对手盘口是否存在价格交叉（即最高买价≥最低卖价），按照价格优先、时间优先消除交叉盘口。

由于能精准复刻交易所撮合逻辑，撮合法广泛适用于高频交易、日内T0策略的模拟交易、策略回测系统等场景，可保障回测结果的真实性与参考价值。 

2.成交消减法（Trade Reduction Method） 

成交消减法，相对来说是一种被动式订单处理机制。

收到新增订单后不做模拟撮合操作，等待交易所推送的后续撤单、成交消息。

然后按消息推送顺序对订单簿中的对应订单进行数量扣减。

3.二者区别

从实际角度来说，这两种方法没有所谓的区别，只需按需采用对应的方法即可。

从原理上来说，而且区别是：

撮合法是主动的，在收到订单时立即检查并撮合，然后更新订单簿。

成交消减法是被动的，它不主动撮合，而是等待成交消息来驱动订单簿的更新。

成交消除法会有一个短暂的订单簿错误情况：比如某个成交单晚到。

撮合法模拟交易所撮合逻辑，订单簿始终实时反映撮合后的状态，结果可预测，适合回测，要求比较高，需要完整实现撮合规则，考虑各种情况。

成交消除法被动等待交易所成交消息，遵循交易所推送时间线，订单簿会短暂处于非法状态，此方法比较简单可靠，适合对基于历史逐笔行情还原生成静态订单薄数据场景。

4.结合交易所撮合机制的理解

实盘交易中，我们订单发给交易所，交易所进行实时模拟撮合，然后发送新增逐笔委托和已撮合产生的逐笔成交信息。

对于我们接收方来说，收到逐笔委托和成交是异步的，但交易所会保证顺序：先有order，然后有trade，当然行情源头，或交易链路上一些异常故障可能会导致乱序。这在实际中是必须要面对的。虽然出现的次数不多。

  

5.撮合法实现思路

1）核心逻辑  

收到新订单时，立即检查是否与对手方存在交叉，如果存在则进行撮合成交，确保订单簿始终处于合法状态。

  

2）实现过程

-   接收新订单。
    
-   检查新订单与对手方订单簿是否存在交叉。
    

-   对于买单，对手方是卖单，如果买单价格>=卖一价，则交叉；
    

-   对于卖单，对手方是买单，如果卖单价格<=买一价，则交叉。
    

-   如果存在交叉，则与对手方订单进行撮合，按照价格优先、时间优先的原则，直到新订单完全成交或交叉消失。
    
-   如果新订单还有剩余，则插入订单簿中。
    

  

3）伪代码

```
# 撮合法的伪代码示例def process_order_with_matching(self, order: Order):"""撮合法处理订单"""# 1. 先与对手方撮合if order.side =="BUY":# 买单：价格 >= 卖一价时撮合while self.asks and order.price >= self.asks[0].price and order.leaves_qty >0:            self._match_with_asks(order)else:# 卖单：价格 <= 买一价时撮合while self.bids and order.price <= self.bids[0].price and order.leaves_qty >0:            self._match_with_bids(order)# 2. 剩余部分插入订单簿if order.leaves_qty >0:        self._insert_to_orderbook(order)# 3. 清理空PriceLevel    self._clean_empty_levels()
```

  

### 6.成交消减法实现思路

1）核心逻辑

严格按照交易所推送顺序处理，不主动撮合，交叉盘口由后续的成交消息自然消除。

2）实现过程

接收新订单，直接插入订单簿（即使存在交叉盘口）。

等待接收成交（Trade）消息，根据成交消息更新订单簿中对应订单的剩余数量，如果剩余数量为0，则删除该订单。

3）伪代码

```
# 成交消减法的伪代码示例defprocess_order_with_reduction(self, order: Order):"""成交消减法处理订单"""# 1. 直接插入订单簿，即使产生交叉    self._insert_to_orderbook(order)# 订单簿可能暂时处于非法状态：# 例如：买一价=10.5，卖一价=10.3 (买价>卖价)# 但保持原样，等待交易所成交消息defprocess_trade_for_reduction(self, trade: Trade):"""通过成交消息消除交叉"""# 1. 找到对应订单    order = self.all_orders.get(trade.order_id)ifnot order:return# 2. 更新订单状态    order.leaves_qty -= trade.qty# 3. 如果订单完成，移除if order.leaves_qty <=0:        self._remove_order(order)# 4. 成交消息可能消除了交叉盘口# 例如：买一订单被成交后，买一价可能下降到低于卖一价    self._clean_empty_levels()
```

  

7.示例演示

假设当前订单簿状态：

-   买一：10.5元 × 100股
    
-   卖一：10.3元 × 80股
    

  

收到新卖单：10.2元 × 150股（价格低于买一价，应撮合）

### 撮合法的处理：

```
# 1. 立即发现交叉：卖单价格10.2 < 买一价10.5# 2. 主动撮合：#    - 以10.5元成交80股（与买一）#    - 剩余70股# 3. 更新订单簿：#    - 买一减少80股，剩余20股#    - 新卖单剩余70股，价格10.2元# 4. 最终状态：#    - 买一：10.5元 × 20股#    - 卖一：10.2元 × 70股
```

###   

### 成交消减法的处理：

###   

```
# 1. 直接插入订单簿：#    - 卖单：10.2元 × 150股#    - 订单簿状态（暂时非法）：#       买一：10.5元 × 100股#       卖一：10.2元 × 150股  # 买价>卖价# 2. 等待交易所成交消息：#    - 收到成交：买一订单成交80股#    - 更新：买一剩余20股# 3. 再等待可能的成交：#    - 可能还有更多成交消息# 4. 最终自然消解交叉
```
