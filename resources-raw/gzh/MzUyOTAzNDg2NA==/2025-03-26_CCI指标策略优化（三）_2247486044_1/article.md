写到这里，想说下量化投资中的“黑盒”问题。

比如我们自己写的CCI这样一个很简单的策略，回测出如上的收益，让我们直接判定策略是否有效、存在哪些问题，都很不容易。

同样，比如我们策略代码中若逻辑存在错误，却可能回测出几百倍的超高收益；有的策略在逻辑层面看似完美无缺，回测收益表现却差强人意。

同理，我们在选择市场上某一个量化基金或者对某个量化基金做出评价的时候，情况和上面基本上相同。鸿沟我认为有两个：专业性和黑盒。

专业性是因为量化这行的确有门槛，即使机器学习，模型这些我们都能听懂，但具体策略怎么用的，每个参数怎么设置的，这个管理人肯定会“黑盒”，而对投资者，隔行如隔山，即使别人愿意说，可能也是听天书，听了后也没有定量的判断力，可能只会增加一些情绪上的加分项，面对这种种复杂状况，根本无法深入探究策略背后的真实情况，最终往往只能依据收益结果来判断策略优劣，形成了 “唯收益结果论” 的局面。

所谓的的尽调，最后只能是市场上的：口口香传的口碑，比如“他们家听起来很厉害”，然后告诉另外一个朋友：“这家不错”。最后投资者趋之若鹜的还是：门口排队最多的那一家。（后来者问前面人，这家好吗？前面人答：都排到这里了，要不买个试试？

开始排查：

策略代码中使用的是bt库自带的计算指标函数，其中cci\_period设置的是20：

```
   self.cci = bt.indicators.CCI(self.data, period=self.p.cci_period)
```

同样的基础数据，采用三种计算CCI方式比较下计算结果：bt库、ta库、人工计算：

```
import pandas as pd
```

结果如图所示：bt库和人工计算的结果相同；ta库计算的指标和bt库和人工计算的都不同。

![](assets/006.png)

再确认下前面todo的极大值的怀疑，发现人工计算的也如此：

![](assets/007.png)

对比了下bt和ta的计算CCI的源码：

bt的源码：

```
tp = (self.data.high + self.data.low + self.data.close) / 3
```

ta的源码：

```
typical_price = (self._high + self._low + self._close) / 3.0
```

二者果然在计算平均偏差、nan值处理，滚动窗口边界上存在不一致，导致了问题。

到这里，我们完全可以下个结论：

策略CCI指标本身应该没问题，以我选择的股票回测看：自2016年1月3日至今天，2200个交易日，按CCI-100的阈值，总共触发了47次，如果我们偏短线风格，这个交易频率肯定是“耐不住的”。至少在这个个股上就没有往下的兴趣了。
