1.基本概念

微软于2016年开发的LightGBM代表了梯度提升算法领域的一项重大进步。

作为与XGBoost和CatBoost并驾齐驱的现代梯度提升算法之一，LightGBM引入了创新技术，使其在性能上能够与XGBoost相媲美的同时，还能提供更高的效率和速度。

LightGBM与其前代模型最大的区别在于引入了两项突破性技术：基于梯度的单侧采样 (GOSS) 和独占特征捆绑 (EFB)。这些创新解决了训练大规模数据集时面临的计算难题，同时还能保持高精度。

**LightGBM中的Goss（Gradient-based One-Side Sampling）**是一种基于梯度的单边采样技术，用于加速梯度提升树的训练过程。

GOSS的核心思想是通过**保留梯度绝对值较大的样本**，同时**随机采样梯度绝对值较小的样本**，来减少计算量。这是因为梯度较大的样本对信息增益的贡献更大，而梯度较小的样本对模型训练的影响相对较小。

## GOSS模式的工作流程如下：

-   **按梯度绝对值排序**：将所有训练样本按照梯度的绝对值从大到小排序
    
-   **保留大梯度样本**：保留前a%的样本（通常a=10%-20%）
    
-   **随机采样小梯度样本**：从剩余的样本中随机采样b%的样本（通常b=10%-20%）
    
-   **调整样本权重**：对随机采样的小梯度样本乘以权重系数(1-a)/b，以保持数据分布不变
    

##   

## 采用GOSS模式在模型训练中的优势：

-   **训练速度提升**：通过减少样本数量，显著加快训练速度
    
-   **内存使用减少**：处理更少的数据，降低内存占用
    
-   **精度保持**：通过保留重要样本，模型精度损失很小
    
-   **防止过拟合**：随机采样小梯度样本增加了多样性
    

##   

## 在LightGBM中，GOSS通常与EFB（Exclusive Feature Bundling）技术结合使用，共同实现高效的梯度提升树训练。

## 使用时可以通过设置`boosting_type='goss'`来启用GOSS算法。

GOSS特别适合处理大规模数据集，在保持模型精度的同时，能够显著提升训练效率。

2.GOSS

要理解 GOSS，我们首先必须研究提升算法如何从错误中学习。当我们观察梯度提升中使用的损失函数时，会发现它涉及对所有训练样本求和。该损失函数由两个关键部分组成：

-   先前的决策树在每个样本上产生的误差；
    
-   新树需要纠正的错误。
    

  

这里有一个关键点：并非所有样本对学习过程的贡献都相同。有些样本误差很大，需要大量修正，而另一些样本已经非常接近正确预测。损失函数的梯度可以精确衡量每个样本需要修正的程度。

如下图中所示的高梯度样本（左）与低梯度样本（右）的可视化对比。顶部的数学公式展示了损失函数，其中梯度项g直接影响每个样本对学习过程的贡献程度。梯度高的样本对修正模型更有帮助，因此我们应该优先选择它们。相反，梯度低的样本提供的新信息较少，可以只进行部分采样而不会显著降低模型的准确率。

高梯度样本远非最优值，需要进一步校正：

-   左侧的样本梯度很高，陡峭的斜率表明该样本距离最小值还很远，需要进行较大的误差修正。
    
-   右侧的样本梯度很低，斜率较为平缓，表明它已经接近最优预测值。

3.GOSS示例分析

通过一个具体的例子来了解 GOSS 在实践中是如何工作。

如上图初始数据集：包含多个特征（蓝色）、目标值（紫色）以及每个样本计算出的梯度（黄色）的训练数据集。

注意：不同样本的梯度值差异，有些样本的梯度值较高（亮黄色），而有些样本的梯度值较低（深黄色）。GOSS 正是利用了这种差异。

![](assets/003.png)

上图根据梯度值对数据进行了排序，并重新组织了数据，排序结果清晰地展现了数据的结构：

-   高梯度样本包含最多的学习信号，则聚集在顶部，
    
-   低梯度样本对模型改进的贡献较小，则聚集在底部。
    

  

这种组织方式为 GOSS 的选择性采样策略奠定了基础。

![](assets/004.png)

图 4：GOSS 采样机制。

上图所示的GOSS 采样机制揭示了 GOSS 技术的核心。该算法将排序后的样本分为两组，所有高梯度样本均被保留（由最高采样率 a 控制），而低梯度样本则被下采样（由其他采样率 b 控制）。重加权公式确保采样后的数据与原始数据保持相似的分布：

-   **高梯度样本（顶部部分）：**保留所有这些样本，因为它们包含最有价值的学习信号。_顶部率_（参数_a_）决定了被视为“高梯度”样本的百分比。例如，如果_a_ = 0.2，则我们保留梯度最高的 20% 的样本。
    
-   **低梯度样本（底部部分）：**从这些样本中随机抽取样本，而不是全部使用。_另一个参数_（参数_b_）决定保留多少比例的低梯度样本。例如，如果_b_ = 0.1，则我们随机选择 10% 的低梯度样本。
    

  

GOSS 的精妙之处就在于此：通过对低梯度实例进行采样，改变了训练数据的分布。如果直接使用这些采样后的数据进行训练，模型就会偏向于高梯度样本。为了弥补这一点，GOSS 应用了一种重加权方案。重新加权公式为：

```
（1 — a）/ b
```

该公式会调整采样得到的低梯度实例的权重，以补偿采样误差。

让我们通过一个具体的例子来理解这一点：

-   假设有1000个训练样本
    
-   将_a_设置为0.2（最高速率），故保留梯度最高的200个样本。
    
-   设定_b_\=0.1（其他速率），从剩余的800个低梯度样本中抽取80个样本。
    

  

重新加权因子变为：

```
(1–0.2) / 0.1 = 0.8 / 0.1 = 8
```

  

为了代表原始的800个实例，80个采样得到的低梯度实例中的每一个都被赋予了8倍的权重。

这种重新加权确保缩减后的数据集与原始完整数据集保持相似的总体分布，从而防止出现偏差，同时提高计算效率。

基于梯度的单侧采样具有显著优势：

-   **训练速度：**通过使用更少的样本（在本例中为 280 个样本而不是 1000 个样本），每棵树的训练速度都显著提高。速度提升幅度与采样率大致成正比。
    
-   **保持准确率：**因为我们保留了所有高梯度样本（信息量最大的样本），并适当地重新加权采样的低梯度实例，所以我们保持了与在完整数据集上训练非常接近的预测准确率。
    
-   **内存效率：**数据量越少，内存需求越低，LightGBM 可以处理传统方法可能无法放入内存的大型数据集。
    
-   **更好的泛化能力：**采样引入了一种正则化形式，可以帮助防止过拟合，因为我们并没有对每一个训练样本进行拟合。
    

  

GOSS 解决了大量样本训练的难题，而独占特征捆绑则着眼于另一个问题：高维稀疏数据。在许多实际应用中，尤其是在自然语言处理、推荐系统和类别编码等领域，我们经常会遇到包含成百上千个特征的数据集，其中大部分特征值都为零。

4.EFB

在高维数据上进行训练计算量巨大，因为梯度提升算法在确定最优分割时必须考虑每个特征。EFB 提供了一种巧妙的解决方案：如果某些特征是互斥的（意味着它们很少同时具有非零值），我们可以将它们合并成一个单一特征，而不会丢失信息。

## 当一个特征的非零值几乎总是对应于另一个特征的零值时，这两个特征被认为_是互斥的。这种情况常见于：_

-   **独热编码分类变量：**如果对一个有100个类别的分类变量进行独热编码，将得到 100个二元特征，其中一次只能有一个特征为 1。
    
-   **罕见事件指标：**代表罕见、互斥事件的特征。
    
-   **文本数据：**在词袋表示中，对于任何给定的文档，大多数词特征为零，并且许多词对很少同时出现。
    

  

![](assets/005.png)

如图上图，特征A和特征B（左）通过偏移特征B的值来合并成一个捆绑特征C（右），以避免与特征A的值冲突。具体步骤如下：

**第1步：确定独有功能**

在图上的左侧，看到两个特征A和B。请注意它们的关键属性：当A具有非零值时（第 2行和第5行），B的值为零，反之亦然（第1行和第4行）。第3行显示两个特征的值均为零，这完全正常。这种互斥性使它们成为理想的捆绑对象。

**第2步：通过偏移值创建捆绑包**

捆绑算法的工作原理如下：

a)对于特征 A 的值：在新捆绑的特征 C 中保留它们原样。

-   例如：第 2 行 A = 1，所以 C = 1
    
-   例如：第 5 行 A = 1，所以 C = 1
    

  

b)对于特征 B 的值：加上一个偏移量，该偏移量等于特征A中的最大值。A中的最大值是1，因此对于B值，计算：C = B + max(A) = B + 1

-   例如：第 1 行 B = 1，所以 C = 1 + 1 = 2
    
-   例如：第 4 行 B = 1，所以 C = 1 + 1 = 2
    

  

c)对于A和B均为零的行：C保持不变。

例如：第 3 行 A = 0，B = 0，所以 C = 0

**第3步：保存信息**

这种方法的优点在于不会丢失任何信息：

-   当 C = 0 时：两个原始特征均为 0。
    
-   当 C = 1 时：特征 A 为 1（且特征 B 为 0）
    
-   当 C = 2 时：特征 B 为 1（且 A 为 0）
    

  

可以通过逆向操作，从特征 C 完美地重构原始特征 A 和 B。

偏移量确保了不同特征的值在组合表示中永远不会冲突。

## 再看一个更实际的例子，看看 EFB 的强大之处。

## 假设有一个分类变量“国家/地区”，它有195个可能的值。

## 经过独热编码（文末介绍）后，你会得到195个二进制特征。

## 对于任何给定的样本，这些特征中恰好有一个为 1，其余 194 个为 0。

  

使用 EFB，则可以将所有195个要素捆绑到一个取值范围为0到195的单个要素中：

-   值 0：未指定国家/地区
    
-   值 1：国家 1（美国）
    
-   值 2：国家 2（加拿大）
    
-   以此类推，直至数值 195。
    

  

将特征数量从195个减少到1个，大大降低了在树构建过程中寻找最佳分割点的计算成本，同时保留了准确预测所需的所有信息。

## 实际上，特征很少是完全互斥的。EFB 仍然可以将“基本”互斥的特征进行捆绑，也就是说，这些特征仅在极少数样本中同时具有非零值。该算法包含一个冲突阈值参数，用于控制可容忍的重叠程度。

##   

当然将近乎独有的功能捆绑在一起时，需要权衡取舍：

某种情况下，会丢失少量信息（在极少数情况下，当两个特征都不为零时）。

减少功能数量可以显著提高速度。

实证研究表明，只要冲突率较低（通常低于 5%），准确率的损失可以忽略不计，而速度的提升则相当显著。

## EFB具有以下几个主要优势：

-   **降低维度：**特征越少，分割查找操作就越快。如果能将 100 个独热编码特征合并成 1 个特征，特征空间就减少了 100 倍。
    
-   **更低的内存占用：**将一个捆绑功能存储起来而不是存储多个单独的功能，可以显著降低内存需求。
    
-   **减少过拟合：**特征越少，模型记忆训练数据中噪声的机会就越少。这有助于提高模型的泛化能力。
    
-   **保持准确性：**当特征真正具有排他性（或几乎具有排他性）时，捆绑可以保留所有预测信息，同时显著提高效率。

## 5.小结

LightGBM 的成功源于其巧妙地结合了基于梯度的单侧采样和专属特征捆绑技术，二者协同工作，共同应对大样本量和高维度的双重挑战：

-   **GOSS**通过将计算资源集中在最重要的样本（梯度高的样本）上，智能地减少训练样本的数量，同时通过仔细的重新加权来保持准确性。
    
-   **EFB**通过将互斥或几乎互斥的稀疏特征捆绑在一起来降低有效维度，从而在不牺牲预测能力的情况下大幅缩小特征空间。
    

  

这些技术的结合使得 LightGBM 的训练速度远超传统的梯度提升方法，同时还能保持甚至提升准确率。与 XGBoost 类似，LightGBM 也采用了基于直方图的分割查找方法来进一步提高效率，但真正使其脱颖而出的是 GOSS 和 EFB 技术。

对于处理大规模数据集（尤其是高维稀疏数据集）的从业者而言，LightGBM 兼具速度和性能的优势。深入了解 GOSS 和 EFB 的底层工作原理，不仅有助于更有效地使用 LightGBM，还能让您洞悉现代机器学习算法如何通过精心设计的算法实现卓越的效率。

附：独热编码（One-Hot Encoding）

简单说，独热编码是把“离散的分类值”转换成“只有0和1的二进制向量”，让模型能读懂非数值型特征。

如原始特征：行业分类（金融、地产、科技、消费等）

 采用独热编码后：

```
金融 -> [1, 0, 0, 0]
```

每一个分类值对应一个“专属位置”，只有这个位置是1，其余全为0（“独热”就是“只有一个是热的/激活的”意思）。

量化场景中用独热编码的场景大概有：

-   非数值型分类因子：比如「股票板块」（主板/创业板/科创板）、「财报季」（Q1/Q2/Q3/Q4）、「市场情绪标签」（恐慌/中性/乐观）；
    
-   无序分类因子：分类之间没有“大小/顺序”关系（比如行业、板块），如果直接把“金融=1、地产=2、科技=3”赋值，模型会误以为“科技>地产>金融”，产生错误逻辑；
    
-   树模型适配：LightGBM/XGBoost对独热编码的兼容度高，但要注意「类别数」（比如行业有30个分类，编码后会新增30列因子）。
    

  

比如在LightGBM中，先对行业分类特征做独热编码，再用编码后的全数值数据训练 LightGBM 模型（GPU 加速）。

### 独热编码是量化模型处理分类因子的基础方法，核心是“把模型读不懂的分类值，转成0/1向量”，但在多因子+GPU/CPU场景中，重点要避“维度爆炸”的坑，优先让LightGBM自动处理分类特征，仅对少量核心分类因子手动编码，既保证精度，又不增加训练/推理的时延和硬件开销。
