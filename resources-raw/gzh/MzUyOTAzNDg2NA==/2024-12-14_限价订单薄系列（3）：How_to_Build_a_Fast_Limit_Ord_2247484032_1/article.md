1.数据结构

如何设计和实现一个高效的限价订单簿（LOB），这对于高频交易系统来说是一个至关重要的组件。文章中讨论了数据结构的选择、主要操作的时间复杂度以及一些优化策略。

为了高效地实现限价订单簿，文章中定义了三个主要的数据结构：

1.  **Order**
    
    表示一个订单，包含订单的唯一标识ID、买卖标志、数量、限价、进入时间、事件时间，以及指向下一个和前一个订单的指针，还有指向父Limit的指针。
    
2.  **Limit**
    
    表示一个限价，包含限价价格、订单数量、总成交量，以及二叉树的父节点、左子节点、右子节点指针，还有该限价下订单链表的头和尾指针。
    
3.  **Book**
    
    表示整个订单簿，包含买入和卖出的Limit树，以及最低卖出价和最高买入价的指针。
    

其中3个数据结构可参考如下定义：

**Order:**

```
int idNumber//订单的唯一标识。
```

**Limit:**

```
int limitPrice//限价价格。
```

**Book:**

```
Limit *buyTree //买入LimitTree
```

### 2.主要操作的时间复杂度

文章中提到，限价订单簿需要实现三个主要操作：添加、取消和执行，并且目标是这些操作都能在O(1)时间内完成。具体来说：

-   **添加操作: 对于第一个到达某个限价的订单，时间复杂度为O(log M)，而对于后续订单，时间复杂度为O(1)。**
-   **取消操作: 时间复杂度为O(1)。**
-   **执行操作: 时间复杂度为O(1)。**
-   **查询询操作：如获取某个限价的成交量或最佳买入价和卖出价，时间复杂度也为O(1)。**

### 3.性能优化方向

**a)数据结构选择:**

-   使用二叉树来管理Limit对象，按限价排序，这样可以高效地进行添加、删除和查询操作。
    
-   每个Limit对象中又有订单的双向链表，这样可以高效地管理同一限价下的多个订单。
    

**b)稀疏数组 vs 二叉树:**

-   使用稀疏数组（稀疏数组（Sparse Array） - 知乎 (zhihu.com)）代替二叉树，可以将添加操作的时间复杂度降低为O(1)，但删除操作的时间复杂度会增加为O(M)。
    
-   如果将Limits存储在稀疏数组中并链接在一起，添加操作的时间复杂度会恢复为O(log M)，而删除操作仍保持O(1)。
    

**c)内存管理**:

-   使用批量分配或对象池来管理Order和Limit对象，以避免垃圾回收的性能开销。
