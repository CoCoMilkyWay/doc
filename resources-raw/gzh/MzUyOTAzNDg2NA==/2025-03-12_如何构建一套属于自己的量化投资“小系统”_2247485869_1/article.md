4.策略模块

策略模块大部分功能其实是做订单管理，比如信号给出：买信号、卖信号、不变等3类信号。

对于买信号，就下单买入委托，则需要：资金管理、委托记录、成交处理、更新持仓、甚至还加入订单有效性检查、风控检查等；

对卖信号，特别对可用做T0的品种来说，除了买信号相关考虑点，还要考虑净头寸概念，比如先是买入信号，买入了1000股某股票，然后此股票上出了1500的卖出信号，则需要先平掉买入1000股头寸，在开空头（卖出）500股，所以这时候就得实时记录当下的净头寸。

需要大家根据具体策略进行设计。

开源好用、广受好评的回测框架，基本上都是国外的，而且大部分都停止了更新，国内量化平台很多，但免费提供开源回测框架sdk的挺少，自己构建也不是没有可能，只是可以先了解轮子，学习轮子，熟悉轮子后，再可以考虑自己设计。

这两天实践过程中遇到个回测问题，正好可以分享下：在使用backtrader时，开始使用的限价报单，报单代码如下：

```
    def _execute_trade(self, size):
```

结果订单状态最终都为：Expired，无成交记录，详细交易流水如下：

```
[2024-07-19] 买入 2000 股 @ 限价0.91
```

这个问题纠结了我两个晚上，也看了backtrader和网上大家对backtrader交易模块的分析，按backtrader逻辑：当订单被创建后，首先会进入Submitted状态，然后被broker模块接受后，状态变成Accepted。之后，如果订单满足条件（比如限价单的价格达到），才会执行并变为Completed或Filled。如果订单一直没有成交，可能会保持Accepted或者变为Expired等其他状态。

在撮合逻辑上，Backtrader在处理日线数据时，通常每个数据点代表一天的四个价格（OHLC）。在回测中，策略的next()函数在每天结束时被调用，生成交易信号。但订单的执行逻辑会根据订单类型有所不同。

-   对于市价单（Market Order），Backtrader默认在下一个交易日开盘时成交，使用开盘价作为成交价。例如，如果在T日的收盘后（即T日的数据处理时）发出买入市价单，订单会在T+1日的开盘时执行，成交价为T+1日的开盘价。这是因为在真实交易中，当日收盘后提交的订单通常会在下一个交易日处理。
    
-   对于限价单（Limit Order），需要满足限价条件才能成交。在日线回测中，Backtrader会检查下一个交易日（T+1日）的价格是否触及限价。例如，如果在T日收盘后设置一个买入限价单，价格为X，那么Backtrader会检查T+1日的最高价是否大于等于X。如果是，则以X或更好的价格成交，通常使用T+1日的开盘价，或根据经纪商的模拟设置（例如，使用OHLC中的最低价、最高价来判断是否触发）。
    
-   止损单（Stop Order）和止损限价单（Stop Limit Order）的逻辑类似，需要价格触发止损点后才会执行，同样在下一个交易日处理
